# Homepage

The homepage is conversion copy for a first-time visitor. The first screen has
to answer what the work is, who it is for, and why this is different:

- What: solve the messy business problems no one wants to own
- Who: owners of small and mid-size companies; sometimes a P&L leader at a
  larger firm, only when there is real leverage
- Why: no framework, no PowerPoint, no packaged solution — the problem in
  front of us, with the tools that are already there

Sequence: opening (statement, who, why, Talk), the kind of problem, the
label vs the actual work (inline SVG arcade), case evidence, how the work
happens (prose, not a numbered method), close. Do not restore the AI-thesis
narrative, three-column benefits, or a step-by-step framework. Those contradict
the differentiator.

The implementation retains the existing forest, ivory, brass, Newsreader and
DM Sans design language. The illustration is an inline SVG arcade transitioning
from a facade to a construction drawing. No archived assets or design have been
restored. The retained office artwork remains separate.

The four case descriptions and metrics come from the earlier supplied
wireframe. They have not been independently verified. Do not punch them up.
More links to the existing About page. Talk uses the existing configured
Cal.com destination.

The Field Notes anchor is always available. The real writing collection can add
article links. Newsletter email collection is not connected: no provider endpoint
has been supplied. Until then the section offers the existing LinkedIn follow link.
Do not add a form that claims to subscribe without a working integration.

The shared header presents Field Notes, About, and Talk directly on desktop and
mobile. Existing About, Teardown, and not-found pages are retained. Teardown is
a starting conversation, not a packaged offer, and is not in primary navigation.
Deployment still requires an explicit request and SPA fallback support for
direct page loads.

Validation: npm run build; desktop and mobile rendering; horizontal overflow;
anchor destinations; keyboard access; reduced-motion rendering. Render checks do
not constitute user acceptance of the composition. No deployment is authorized.
